# Publishing a build to Steam

How a build on this machine becomes a build Steam will install. Doing this at
least once is the remaining gate on two things nothing here can test: accepting
a Steam **invite**, and unlocking an **achievement** (porting-plan.md, Phase 6).

Read [exporting.md](exporting.md) first — it covers producing the build. This
document covers only what happens after there is one.

---

## 1. What is involved

| Thing | What it is | Where it comes from |
|---|---|---|
| **App ID** | `1821800`, the published game's id | Decided in decisions.md D57 |
| **Depot ID** | The container of files inside that app | The partner site. **Not** the App ID, and not safe to guess |
| **Branch** | A named version of the game | You create it on the partner site |
| **SteamPipe** | Valve's upload tool, driven by `steamcmd` | The Steamworks SDK |
| **Build scripts** | Two small text files telling SteamPipe what to upload | Generated by `tools/steam_upload.ps1` |

Nothing above is in this repository. The SDK is **not redistributable** and is
gitignored; the build scripts carry a local path and a depot id, so they are
generated fresh each time rather than committed.

---

## 2. One-time setup

1. Sign in to the Steamworks partner site.
2. Open the app **1821800**.
3. Go to **SteamPipe > Depots**.
4. Write down the **Depot ID**. It is a number close to the App ID but it is
   its own value, and uploading into the wrong one is not something you want
   to discover afterwards.
5. Go to **SteamPipe > Builds**, and note that the list is empty until you have
   uploaded something.
6. Download the **Steamworks SDK** from the partner site (Documentation >
   SDK, or `partner.steamgames.com/downloads/steamworks_sdk.zip`).
7. Extract it **outside this repository**. It must never be committed, even to
   a private repo.
8. Find `tools\ContentBuilder\builder\steamcmd.exe` inside what you extracted.
   That is the uploader.

---

## 3. Every time: export, then upload

1. Export the release build. From the project root, in PowerShell:

   ```
   & <godot> --headless --path . --export-release "Windows Release"
   ```

   `<godot>` is the console executable; [development.md](development.md) says
   where it lives on a given machine.

   That writes to `..\stalks-release\`. It is a **different** preset and a
   different folder from the everyday debug build in `..\stalks-build\`, and
   it leaves out the test suite and GUT.

2. Generate the build scripts:

   ```
   .\tools\steam_upload.ps1 -DepotId <the number from step 2.4> -Branch testing
   ```

   It checks the folder holds a real build, refuses if `steam_appid.txt` has
   found its way in, lists exactly what will be uploaded, and prints the
   upload command. It does **not** upload.

3. Read the file list it printed. Four files: the `.exe`, the `.pck`, and two
   DLLs. If anything else is there, stop and work out why.

4. Run the printed command from the SDK's
   `tools\ContentBuilder\builder` folder. You will be asked for your password
   and a Steam Guard code.

5. Back on the partner site, check **SteamPipe > Builds**. The new build should
   be listed against the `testing` branch.

6. Set the branch live if the upload did not already: **SteamPipe > Builds**,
   choose the build, set it live on `testing`.

7. Give the `testing` branch a password on the **Builds** page, and give that
   password to whoever is testing with you.

---

## 4. Installing the test branch

1. In the Steam client, right-click **Stalks Stalks Stalks** > **Properties**.
2. Open the **Betas** tab.
3. Enter the branch password and click **Check Code**.
4. Choose `testing` from the dropdown.
5. Wait for the download.

## 5. What the upload unblocks

Two tests that cannot run against a locally built copy, both because the game
has to be what App ID 1821800 actually installs (D57):

1. **Accepting an invite.** Invite a second account from the Steam overlay. It
   should join the lobby. The sending half is already tested; what has never
   run is Steam launching the game with `+connect_lobby` behind it.
2. **Unlocking an achievement.** Win a game. `SSS_Win_One_Game` should unlock.
   This is deliberately untested so far because it awards permanently on a real
   account.

Both are in [manual-testing.md](manual-testing.md).

**Also still unverified:** the four Steam *stat* names (`sss_wins`,
`sss_loses`, `lifetime_networth`, `sss_yeehaws`). They are unambiguous in the
original's source but have never been checked against the partner backend. The
partner site's **Stats & Achievements** page is where to confirm them; a
mistyped stat name fails silently.

---

## 6. Before the default branch

`default` is what everybody who owns the game gets. `tools\steam_upload.ps1`
refuses it unless you pass `-AllowDefaultBranch`, on the grounds that it should
never be a typo.

Before going there: the game is a port of a published Unity title, and
replacing the published build is a decision about the store page, the existing
owners and their achievements, not a build step. Nothing in this repository
decides it.
